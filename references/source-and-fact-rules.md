## 1. 来源分类

| 来源 | 允许用途 | 不得直接推导 |
|---|---|---|
| 用户明确确认 | 项目名称、边界、目标和特殊处理 | 未确认的其他变量 |
| 正式批复或立项材料 | 单位、背景、投资控制、资金来源、工期 | 文件未载明的技术细节 |
| 医院正式材料 | 医院概况、现状、业务量、现有系统 | 无依据的评价和结论 |
| 客户建设清单 | 本期范围、数量、建设属性 | 价格和验收完成度 |
| 公司能力清单 | 产品映射、能力覆盖和缺口 | 客户最终范围 |
| 厂商方案 | 技术路线、功能、接口和迁移线索 | 院方正式决策和最终价格 |
| 报名或响应材料 | 现状线索、历史报价、产品能力 | 正式事实和批复概算 |
| 外地参考可研 | 结构、论证方式和表格形式 | 地域、单位、范围、投资、指标、结论 |
| 政策标准 | 政策依据、合规要求和评价标准 | 医院现状和项目特有事实 |
| Word模板 | 样式、页面、编号、目录和版式 | 模板旧正文和元数据 |

## 2. 默认优先级

1. 用户在当前项目中明确确认的口径；
2. 正式批复、立项、院方盖章或正式发布材料；
3. 当前确认版客户建设清单；
4. 医院正式现状和调研材料；
5. 已经院方确认的厂商技术方案；
6. 未经确认的供应商、报名和调研响应材料；
7. 官方公开政策、标准和规范；
8. 外地同类项目和历史参考稿。

优先级仅决定可使用程度，不自动消解冲突。

## 3. 事实状态

| 状态 | 使用规则 |
|---|---|
| `【已确认】` | 用户明确确认或正式文件支持，可确定表述 |
| `【材料明确】` | 材料明确但未正式确认，审慎表述并保留来源 |
| `【待确认】` | 有说法但口径未确认，不得写成确定事实 |
| `【待补充】` | 无资料，保留明确占位 |
| `【冲突】` | 来源不一致，列出不同口径 |
| `【分析建议】` | 基于范围、政策或行业逻辑提出，与事实分开 |
| `【仅作参考】` | 仅支持结构、功能或市场线索 |
| `【不适用】` | 经确认与本项目无关，不进入正文 |

不要使用“基本确认”“大致明确”“待核实”等自造状态。

## 4. 原子事实提取

- 每条事实只表达一个可独立判断真假的命题。
- 同一段中包含单位、时间、数量、状态时，拆成多条事实。
- 数字必须同时登记单位和统计时点；缺失时明确留空。
- 证据位置优先使用页码、表名、单元格、标题路径或段落序号。
- 原文为推测、计划、建议、预计时，事实内容必须保留语气。
- 文件名中的日期不自动视为统计时点。
- 报名材料中的联系人、电话和厂商自述不进入项目事实卡。

## 5. 冲突处理

1. 为冲突组建立 `CONFLICT-xxx`。
2. 分别记录各来源口径、证据位置、日期和状态。
3. 说明冲突影响：项目边界、投资、技术方案或文字完整性。
4. 不自行选择一个“看起来更合理”的值。
5. 用户确认后新增确认记录，不删除历史冲突条目。

## 6. 缺失资料和确认问题

缺失资料按以下层级排列：

1. 影响项目边界；
2. 影响投资；
3. 影响技术方案；
4. 影响文字完整性。

第一轮确认问题最多15项，只问答案不同会改变范围、投资、技术路线、验收目标、工期或报告结论的事项。可通过文件查到的问题先检索文件，不询问用户。

## 7. 敏感信息

- 默认识别姓名、手机号、身份证号、邮箱、详细住址和未公开报价。
- 资料登记表可以记录“包含个人信息”，但交付正文默认不携带联系方式。
- 复盘和Skill资产必须脱敏，不打包客户原文、联系人、未公开金额和访问凭据。
- 输出扫描结果时只显示必要上下文，不扩大敏感信息暴露。
