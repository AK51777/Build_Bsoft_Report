# 文档标准、格式画像和缩进规则

## 1. 前置识别

格式处理从阶段0开始，不等到Word合并时再决定。顺序为：

`文档类型 → 地方编制要求 → 正式模板 → 格式画像 → 样式契约 → 语义化正文 → Word映射 → 格式检查`。

匹配优先级：用户明确要求 > 项目所在地现行正式标准 > 用户提供正式模板 > 同地区同类型已确认模板 > 通用政府投资模板。

## 2. 语义样式契约

Markdown或中间数据只表达 `heading_1`、`heading_2`、`heading_3`、`body`、`list`、`table_body`、`caption` 等语义，不写死字体和缩进。

Word/WPS输出时：

- 标题绑定真实段落样式和 `outlineLvl`；
- 多级编号优先复用模板 `numbering.xml`；
- 不同时使用手写编号和Word自动编号；
- 正文字体、字号、行距和首行缩进由样式控制；
- 表格、列表、标题和题注不继承正文首行缩进；
- 非白名单情况不写段落级 `w:ind`、`w:spacing`、`w:tabs`。

## 3. 缩进问题处理

生成前：删除段首Tab、普通空格和全角空格；禁止用空格模拟缩进。

生成时：按语义应用样式；列表使用列表样式；表格单元格使用表格正文样式；横向节不复制异常段落属性。

生成后：检测前导空白、直接缩进、直接Tab位、未绑定样式、未知样式、标题样段落未使用标题样式和标题运行级直接格式。

P1默认只检测，不自动修改源文件。自动规范化必须：

1. 复制候选稿；
2. 仅修复规则明确、可逆的项目；
3. 输出修复日志；
4. 重新渲染全部页面；
5. 复核标题、目录、表格、页码和分页。

## 4. 格式画像确认

从参考Word提取的画像只是候选。用户确认前不得假定它等于当地正式编制标准。画像至少保存页面设置、分节、样式、层级、编号哈希、样式使用频率和直接格式统计。

用户确认后，另存项目本地 `word-format-authority.json`，不要修改画像文件来表达确认。配置应绑定只读 DOCX 权威原件及哈希、画像与样式契约证据及哈希、语义样式映射、确认人和确认时间；`project-config.json` 只保存该配置的相对路径。这样更换地区模板或扩展样式时只替换项目配置，不修改清单匹配、正文装配或通用 Skill 规则。

标准方案正文只有 `plain_text` 时，只能依靠 `heading_path` 恢复语义标题，再映射到格式权威的 Word 样式；不能声称保留原标准方案的字体、表格、图片或运行级格式。需要逐对象保真时，必须从标准 DOCX 重新构建 `structured_json` 或 `ooxml_fragment` 内容负载。
