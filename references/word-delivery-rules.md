# Word合并、排版和交付规则

## 目录

1. 模板处理
2. Markdown到Word映射
3. 节和横向宽表
4. 页眉页脚和页码
5. 清理要求
6. 渲染验证
7. 交付记录

## 1. 模板处理

- 原始参考Word只读。
- 先复制为脱敏候选模板，再删除旧正文、旧图片、批注、超链接和文档属性。
- 只保留经确认需要复用的页面设置、样式、编号、目录和表格样式。
- 不要把参考项目页眉页脚或封面信息当成样式资产。
- 模板清理后先单独打开和渲染验证。

## 2. Markdown到Word映射

- `#` 至 `######` 分别映射到确认的 Word `Heading 1` 至 `Heading 6` 样式，不直接显示 `####` 等 Markdown 标记。
- 标题编号优先复用模板的多级列表定义。
- 正文、表题、图题、引用、列表和表格分别映射到稳定样式。
- 动态目录使用Word字段，不写死页码。
- Markdown HTML注释作为工作层信息，转换时过滤。
- 不将文件名或章节分隔标记写入正文。
- `**加粗**`、`*斜体*`、行内代码和链接转换为 Word 语义对象；正式稿的 Markdown 残留计数必须为零。

## 3. 节和横向宽表

- 先根据列数、文本长度和目标纸张判断宽表。
- 横向节只包裹需要横向的表格及必要表题。
- 横向节前后恢复纵向页面设置。
- 检查节前后是否产生空白页。
- 表格列宽、重复表头、跨页断行和单元格边距必须实际渲染验证。

## 4. 页眉页脚和页码

- 明确首页、奇偶页和普通页是否不同。
- 新节继承关系必须符合设计，不能无意继承参考稿页眉页脚。
- 页码字段在横向节前后连续。
- 目录页码和正文页码的编号体系按项目要求设置。

## 5. 清理要求

检查DOCX包中的：

- `word/header*.xml` 和 `word/footer*.xml`；
- 批注、修订和人物信息；
- `docProps/core.xml` 和 `docProps/custom.xml`；
- 旧媒体、嵌入对象和外部链接；
- 隐藏文本和旧书签；
- 参考项目名称和供应商专名。

不得只删除可见正文。

## 6. 渲染验证

交付前执行：

1. 打开并重新保存候选DOCX。
2. 更新目录和域。
3. 渲染为PDF或逐页图片。
4. 检查封面、目录、每章首页、横向页、超宽表、分页处和末页。
5. 检查截断、重叠、字体替换、空白页、表格越界、页码断裂和目录换行。
6. 执行参考残留词扫描。

没有渲染检查，不得声称Word排版完成。

正式稿还必须由数据库当前组装内容生成，并绑定最新通过的 `full_report_delivery` 校验、已确认模板哈希和独立 `delivery-artifact-audit.json`。直接调用转换器、缺构建摘要、使用陈旧校验或修改已采纳正文后不重跑校验，均不得进入交付状态。默认转换模式只生成带工作稿标识的文件。

## 7. 交付记录

记录：

- 输入模板和正文版本；
- 合并脚本或工具版本；
- 生成时间；
- 章节、标题、表格、节和横向节数量；
- 页数和目录状态；
- 残留扫描结果；
- 已知占位和未解决问题；
- 原始文件未被修改的确认。

## 8. V0.2样式契约与缩进治理

1. 先运行 `extract_document_profile.py` 提取参考文档的页面、段落样式、标题层级、多级编号和表格特征，人工确认后形成项目样式契约。
2. Markdown只表达语义层级；合并时将语义对象映射到Word命名样式，不在Markdown中写空格、Tab或字号模拟排版。
3. 正文缩进优先写入样式定义；仅对确有例外的段落使用直接格式，并在交付记录中说明。
4. Word单位统一使用twip或EMU保存，比较时按容差换算，避免厘米、磅和字符单位混用造成误报。
5. 对中文正文重点检查首行缩进、悬挂缩进、列表对齐位、制表位、段前段后、固定值/多倍行距以及表格单元格内边距。
6. 运行 `lint_docx_format.py` 后，阻断级问题必须修复；信息级差异可在确认后写入例外清单。

缩进修复优先级：先清除连续空格和Tab伪缩进，再清理段落直接格式，最后统一命名样式和多级编号。不得对全篇盲目批量设置首行缩进，因为标题、列表、表格、题注和代码块的规则不同。
