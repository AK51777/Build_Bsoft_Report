# 目录、贯通矩阵和章节任务包

## 目录

1. 先矩阵后目录
2. 目录形成
3. 章节任务包
4. 证据骨架
5. 跨章口径
6. 章节完成判定

## 1. 先矩阵后目录

先建立以下链条，再设计章节：

`现状问题 → 建设需求 → 建设内容 → 投资分项 → 绩效指标 → 预期效益`

检查：

- 问题是否有事实或政策依据；
- 需求是否真正回应问题；
- 建设内容是否在范围基线内；
- 投资是否关联建设内容；
- 指标是否可由建设内容实现和评价；
- 效益是否由建设结果合理推导。

断链项标记为待补充，不用套话掩盖。

## 2. 目录形成

1. 识别用户指定的参考目录和必须保持的章节顺序。
2. 保留政府投资可研的法定或常见论证模块。
3. 根据项目个性化范围增删技术、应用、数据、安全、实施和投资章节。
4. 细化到三级标题；标题应表达要回答的问题或建设对象。
5. 用户要求后续粘贴专项方案时，保留稳定章节编号和必要衔接说明。
6. 不为目录中不存在的范围创造建设内容。

目录必须经过“生成候选版→人工审阅确认→按确认版组装”三步：

1. `build_report_outline.py` 根据当前章节计划和建设内容四至七级动态节点生成完整一至七级候选目录，并把来源签名、目录哈希和版本写入数据库；
2. 审阅人可调整候选目录的展示标题，再由 `confirm_report_outline.py` 显式确认；不得增删、重排来源节点、改变层级或偷换来源对象，需调整顺序时应先修改章节组合计划；
3. `assemble_report_markdown.py` 默认只接受当前来源签名对应的确认版目录。章节计划、范围能力映射或动态节点变化后，旧确认自动失效并形成新候选，未经再次确认不得进入交付组装。

确认版目录是正文标题、顺序和交付核验的唯一目录口径。后续改动必须形成新版本，并记录原因、审阅人和受影响章节。

## 3. 章节任务包

每章至少明确：

- 章节目的；
- 必须回答的问题；
- 允许使用的事实ID；
- 对应范围ID；
- 允许参考的来源和章节；
- 禁止继承内容；
- 必备表格；
- 待补充项；
- 跨章共用口径；
- 建议篇幅和行文要求；
- 完成条件和校验规则。

任务包应足以让新的Codex任务在不依赖历史对话的情况下继续编写。

## 4. 证据骨架

正文生成分两遍：

第一遍只写：

- 章节结论；
- 支撑事实ID；
- 范围ID；
- 必要政策依据；
- 关键表格；
- 待补充和待确认位置。

第二遍补充：

- 因果论证；
- 通用定义；
- 章节衔接；
- 政府投资可研要求的必要说明；
- 审慎的分析建议。

禁止先生成完整套话再倒推事实。

## 5. 跨章口径

以下内容必须建立全局唯一口径：

- 项目正式名称和建设单位；
- 建设目标和验收等级；
- 建设范围数量；
- 建设方式；
- 投资总额和资金来源；
- 建设周期和实施阶段；
- 技术路线、部署方式和灾备口径；
- 绩效目标及完成时间。

口径变化时先改事实卡和变更记录，再同步正文。

## 6. 章节完成判定

一章只有在以下条件满足时才标记完成：

1. 任务包要求均有承载；
2. 确定事实可追溯；
3. 范围未遗漏、未越界；
4. 占位已登记；
5. 与前后章和全局口径一致；
6. 完成本章校验；
7. 文件已保存到项目目录。
